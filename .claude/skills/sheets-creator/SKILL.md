# sheets-creator: 악보 → 가사 txt

악보 사진이나 PDF에서 가사를 읽어서, 송폼 순서대로 펼친 `.txt` 파일을 만든다. 이 파일은 보통 예배 자막, PPT, 가사 프린트용으로 쓰인다. 그래서 **실제로 부르는 순서**대로 적고, **마디 기준으로 줄을 끊어서** 화면 한 장에 들어갈 분량이 일정하게 유지되게 한다.

## 작업 순서

### 1. 악보를 눈으로 볼 수 있게 준비

- 이미지(jpg/png/heic 등)는 Read 도구로 바로 열어서 본다.
- PDF는 페이지를 이미지로 바꾼 뒤 각 페이지를 Read로 연다:
  ```bash
  python3 <이 스킬 경로>/scripts/pdf_to_images.py <악보.pdf> <출력폴더>
  ```
  스크립트가 만든 PNG 경로를 출력한다. 글자가 작아서 안 읽히면 `--dpi 300`으로 다시 만든다.
- 여러 장이면 모든 페이지를 순서대로 다 본 다음에 정리를 시작한다. 송폼이나 2절 가사가 뒷장에 있는 경우가 많다.

### 2. 송폼 찾기

송폼은 악보 어딘가에 적혀 있다. 보통 제목 근처나 맨 위·맨 아래 여백이고, 손글씨로 적혀 있기도 하다. 예를 들면:

```
Intro(4) - V1 - V2 - P.C. - C - C - B - C - Outro
I - V - P.C - C - V - P.C - C - B(4) - C - O
```

송폼에 쓰이는 표기:

| 표기 | 뜻 |
|---|---|
| `Intro`, `I` | 전주 |
| `V`, `V1`, `V2`, `Verse` | 절 (V1 = 1절, V2 = 2절) |
| `P.C.`, `PC`, `Pre`, `Pre-Chorus` | 프리코러스 |
| `C`, `Chorus` | 후렴 (C1, C2처럼 번호가 붙기도 함) |
| `B`, `Bridge` | 브릿지 |
| `Inter`, `Interlude` | 간주 |
| `Outro`, `O`, `Ending` | 후주 |
| `(4)`, `(8)` 같은 괄호 숫자 | **마디 수**. 예: `Intro(4)`는 4마디짜리 전주 |

악보 본문에도 파트 표시가 박스나 글자로 붙어 있다(예: 마디 위에 `V`, `C`, `B`). 송폼 표기와 본문 표시를 맞춰서 각 파트가 악보의 어느 마디부터 어느 마디까지인지 파악한다.

송폼 일부가 화이트·테이프 등으로 **지워져 있으면** 그 칸은 쓰지 않는 파트라는 뜻이다. 송폼 줄과 본문 양쪽에서 그 칸을 통째로 빼고, 주변 메모로 원래 내용을 추측해 채우지 않는다. 예를 들어 `C*2 - (지워짐) - C`는 `C*2 - C`로 적는다. 지워진 칸이 있었다는 사실은 txt에 넣지 않고 작업 후 사용자에게만 알린다.

송폼이 아예 안 보이면 악보에 적힌 순서와 반복 기호(도돌이표, D.S., D.C., Coda, 1.·2. 괄호)를 따라 부르는 순서를 직접 추정한다. 그리고 txt 맨 위 송폼 줄 끝에 `(악보에 송폼 없음 – 추정)`이라고 적어서 사용자가 알 수 있게 한다.

### 3. 마디별로 가사 읽기

각 파트마다 마디 단위로 가사를 읽는다. 마디는 세로줄(barline) 기준으로 센다.

- **음표 하나에 글자 하나씩** 떨어져 있는 한국어 가사는 붙여서 단어로 만든다(`주 - 님 - 의` → `주님의`). 띄어쓰기는 원래 문장에 맞게 자연스럽게 복원한다.
- 영어 가사의 하이픈(`glo - ry`)도 붙인다(`glory`).
- **여러 절 가사가 위아래로 겹쳐** 있으면(앞에 `1.`, `2.`가 붙은 줄) 윗줄은 V1, 아랫줄은 V2로 쓴다. 후렴에 가사가 한 줄만 있으면 모든 후렴이 같은 가사다.
- **못갖춘마디**(첫 마디 앞의 짧은 시작 음)의 가사는 바로 뒤 첫 마디에 붙인다.
- 한 단어가 마디 경계에 걸쳐 있어도 여기서는 신경 쓰지 않는다. 줄을 어디서 끊을지는 4단계에서 띄어쓰기 기준으로 정한다.
- 가사가 없는 마디(쉼표, 반주)도 **마디 수에는 포함**한다. 줄을 끊는 기준이 마디이기 때문이다.

### 4. 줄 나누기: 2마디 = 1줄, 4마디 = 1묶음

이게 이 스킬의 핵심 규칙이다. 자막 한 장에 들어가는 분량을 일정하게 맞추려는 것이다.

- 가사 **2마디를 한 줄**에 쓴다.
- **4마디(2줄)마다 빈 줄**을 하나 넣어서 묶음을 나눈다.
- **4마디 묶음은 가사가 있는 한 항상 2줄**로 만든다. 끝 음을 길게 끄는 곳이 많아서, 단어가 2마디 경계에 걸치는 일이 흔하다. 이때 단어를 통째로 한쪽으로 옮기면 묶음이 1줄로 줄어 버린다. 대신 2마디 경계에 **가장 가까운 띄어쓰기 자리**에서 줄을 나눈다. 단어 중간에서는 자르지 않는다.
  - 악보: `주 하나님 간절히 기도하 | 오니` (3마디째부터 "하오니"를 길게 끎)
  - 결과: `주 하나님 간절히` / `기도하오니`
  - 악보: `그들의 땅을 고치 | 리라`
  - 결과: `그들의 땅을` / `고치리라`
  - 묶음 가사 전체가 띄어쓰기 없는 한 단어라서 나눌 자리가 없을 때만 1줄로 둔다.
- 파트가 4의 배수가 아니면 마지막 묶음은 1줄이 될 수 있다. 그대로 둔다.
- 2마디가 통째로 가사 없이 비어 있으면 그 줄은 생략한다. 그래도 마디 세기는 계속 이어서, 다음 줄이 원래 위치에서 시작되게 한다.
- 파트가 바뀌면 새 묶음을 시작한다. 마디를 이전 파트에서 이어 세지 않는다.

### 5. 송폼 순서대로 펼쳐 쓰기

송폼에 나온 순서 그대로 파트를 하나씩 적는다. 후렴이 세 번 나오면 후렴 가사를 세 번 다 적는다. 이 파일을 그대로 자막 순서로 쓸 수 있어야 하기 때문이다.

- 가사가 없는 파트(Intro, Interlude, Outro 등)는 라벨만 적는다. 마디 수를 알면 같이 적는다(`[Intro] (4)`).
- 같은 파트가 반복될 때 가사가 달라지면(예: 2번째 후렴 마지막 줄만 다름, 1.·2. 괄호) 그 반복 차례에 맞는 가사를 쓴다.
- 송폼에 `C x2`나 `C(8)`처럼 반복·확장이 적혀 있으면 그만큼 펼친다.

## 출력 형식

UTF-8 `.txt` 파일 하나. 파일 이름은 `<곡 제목>.txt`. 제목을 모르면 원본 파일 이름을 쓴다. 사용자가 저장 위치를 말하지 않았으면 원본 악보와 같은 폴더에 저장한다.

```
곡 제목
송폼: Intro(4) - V1 - P.C. - C - V2 - P.C. - C - B - C - Outro

[Intro] (4)

[V1]
(1~2마디 가사)
(3~4마디 가사)

(5~6마디 가사)
(7~8마디 가사)

[P.C.]
...

[C]
...

[Outro]
```

- 파트 라벨은 대괄호로 감싸고, 악보 송폼 표기를 따른다(`[V1]`, `[P.C.]`, `[C]`, `[B]`).
- 파트와 파트 사이에는 빈 줄 하나를 둔다.
- 코드, 계이름, 반복 기호, 셈여림 같은 가사가 아닌 글자는 넣지 않는다.

### 예시

악보: 송폼 `Intro(4) - V - C - C - Outro`, V는 8마디, C는 6마디.

```
주님의 사랑
송폼: Intro(4) - V - C - C - Outro

[Intro] (4)

[V]
주님의 사랑 날 감싸네
어두운 밤도 두렵지 않아

주의 손 잡고 걸어가리
영원히 함께 하리라

[C]
할렐루야 찬양해
나의 주님 높이리

영원토록

[C]
할렐루야 찬양해
나의 주님 높이리

영원토록

[Outro]
```

## 확실하지 않을 때

악보가 흐리거나, 손글씨이거나, 잘려 있으면 추측한 글자 뒤에 `[?]`를 붙인다(`주님의 사[?]랑`). 작업이 끝나면 사용자에게 다음을 짧게 알린다.

- 저장한 파일 경로
- 사용한 송폼 (악보에 있었는지, 추정했는지)
- `[?]`를 붙인 곳, 마디 수가 애매했던 곳

그러면 사용자가 어디를 다시 확인해야 하는지 바로 알 수 있다.
