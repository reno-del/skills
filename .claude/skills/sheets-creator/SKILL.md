# sheets-creator: 악보 → 가사 txt

악보 사진이나 PDF에서 가사를 읽어서 `.txt` 파일을 만든다. 이 파일은 예배 자막/PPT 프로그램에 그대로 붙여 넣어 쓴다. 빈 줄로 나뉜 **묶음 하나가 화면 한 장**이 되고, 묶음은 **항상 2줄**이다. 그래서 다음 세 가지가 중요하다.

- 실제로 부르는 순서대로 적는다.
- 한 화면에 들어가는 분량을 일정하게 맞춘다.
- 가사 말고는 아무것도 넣지 않는다.

`references/example.txt`는 사용자가 직접 정리한 결과물(세 곡짜리 콘티)이다. 줄을 어디서 끊는지, 한 묶음에 몇 마디를 넣는지는 규칙만으로 다 설명되지 않는다. 작업 전에 꼭 한 번 읽고 그 감각을 따른다.

## 작업 순서

### 1. 악보를 눈으로 볼 수 있게 준비

- 이미지(jpg/png/heic 등)는 Read 도구로 바로 열어서 본다.
- PDF는 페이지를 이미지로 바꾼 뒤 각 페이지를 Read로 연다:
  ```bash
  python3 <이 스킬 경로>/scripts/pdf_to_images.py <악보.pdf> <출력폴더>
  ```
  스크립트가 만든 PNG 경로를 출력한다. 글자가 작아서 안 읽히면 `--dpi 300`으로 다시 만들거나, 필요한 부분만 잘라서 확대해 본다.
- 여러 장이면 모든 페이지를 순서대로 다 본 다음에 정리를 시작한다. 송폼이나 2절 가사가 뒷장에 있는 경우가 많다.
- 파일이 여러 개이거나 한 PDF에 여러 곡이 있으면 콘티다. 사용자가 순서를 말해 주면 그 순서를, 아니면 파일·페이지 순서를 따른다.

### 2. 송폼 찾기

송폼은 악보 어딘가에 적혀 있다. 보통 제목 근처나 맨 위·맨 아래 여백이고, 손글씨로 적혀 있기도 하다. 예를 들면:

```
Intro(4) - V1 - V2 - P.C. - C - C - B - C - Outro
I - V - P.C - C - V - P.C - C*2 - B(4) - C - O
```

송폼에 쓰이는 표기:

| 표기 | 뜻 |
|---|---|
| `Intro`, `I` | 전주 |
| `V`, `V1`, `V2`, `Verse` | 절 (V1 = 1절, V2 = 2절) |
| `P.C.`, `PC`, `Pre`, `Pre-Chorus` | 프리코러스 |
| `C`, `Chorus` | 후렴 (C1, C2처럼 번호가 붙기도 함) |
| `B`, `Bridge` | 브릿지 |
| `Inter`, `Interlude` | 간주 |
| `Outro`, `O`, `Ending` | 후주 |
| `(4)`, `(8)` 같은 괄호 숫자 | **마디 수**. 예: `Intro(4)`는 4마디짜리 전주 |
| `*2`, `x2` | 그 파트를 2번 반복 |
| `기도` 같은 한글 메모 | 가사 없는 진행 (기도, 멘트 등) |

악보 본문에도 파트 표시가 박스나 글자로 붙어 있다(예: 마디 위에 `V`, `C`, `B`). 송폼 표기와 본문 표시를 맞춰서 각 파트가 악보의 어느 마디부터 어느 마디까지인지 파악한다. 악보가 두 버전으로 나뉘어 있으면(예: 오른쪽에 `Key up` 버전) 송폼에서 그 지점 이후 파트는 그 버전의 가사를 쓴다. 두 버전의 가사가 다를 수 있다.

송폼 일부가 화이트·테이프 등으로 **지워져 있으면** 그 칸은 쓰지 않는 파트라는 뜻이다. 통째로 빼고, 주변 메모로 원래 내용을 추측해 채우지 않는다. 지워진 칸이 있었다는 사실은 작업 후 사용자에게만 알린다.

송폼이 아예 안 보이면 악보에 적힌 순서와 반복 기호(도돌이표, D.S., D.C., Coda, 1.·2. 괄호)를 따라 부르는 순서를 직접 추정한다. 추정했다는 사실은 사용자에게 알린다.

### 3. 마디별로 가사 읽기

각 파트마다 마디 단위로 가사를 읽는다. 마디는 세로줄(barline) 기준으로 센다.

- **음표 하나에 글자 하나씩** 떨어져 있는 한국어 가사는 붙여서 단어로 만든다(`주 - 님 - 의` → `주님의`). 띄어쓰기는 원래 문장에 맞게 자연스럽게 복원한다. 예를 들어 `나 의 백 성 이 다`는 `나의 백성이 다`이고, `백성이다`가 아니다.
- 영어 가사의 하이픈(`glo - ry`)도 붙인다(`glory`).
- **여러 절 가사가 위아래로 겹쳐** 있으면(앞에 `1.`, `2.`가 붙은 줄) 윗줄은 V1, 아랫줄은 V2로 쓴다. 후렴에 가사가 한 줄만 있으면 모든 후렴이 같은 가사다.
- **못갖춘마디**(첫 마디 앞의 짧은 시작 음)의 가사는 바로 뒤 마디에 붙여서 센다.
- 가사가 없는 마디(쉼표, 반주)도 마디 수에는 포함한다.

### 4. 묶음과 줄 나누기

**묶음 = 화면 한 장 = 2줄.** 묶음 사이에는 빈 줄 하나를 둔다.

**한 묶음에 넣을 분량:**
- 기본은 **4마디 = 1묶음(2줄)**, 한 줄에 2마디 정도다.
- 8마디 가사가 짧아서 4마디씩 한 줄에 편하게 들어가면 **8마디 = 1묶음**으로 합친다. 한 줄이 한 문장처럼 읽혀야 하고, 대략 15자 안팎이어야 한다. 예: `하늘에서 듣고 죄를 사하며` / `그들의 땅을 고치리라`
- 반대로 한 줄에 다 들어가더라도 음을 길게 끌며 한 구절씩 부르는 곳이면 4마디 묶음으로 둔다. 화면이 노래보다 앞서 나가지 않게 하려는 것이다. 예: `주 하나님` / `간절히 기도하오니`, `상한 이 땅` / `새롭게 하소서`
- 파트가 바뀌면 새 묶음을 시작한다. 한 묶음에 두 파트를 섞지 않는다.

**줄을 끊는 자리:** 마디 경계를 기준으로 삼되, 실제로는 **뜻이 끊기는 자리**에서 자른다. 단어 중간에서는 자르지 않는다.
- 다음 말을 꾸미는 짧은 말은 다음 줄로 보낸다. 악보에서 `구하여서 그 | 악한 길`이라도 `나의 얼굴을 구하여서` / `그 악한 길 떠나면`으로 쓴다.
- 부르는 말("주 하나님", "아버지여")은 따로 한 줄로 세워도 된다.
- 두 줄 길이가 너무 차이 나지 않게 한다.

**`-` 채우기:** 묶음에 가사가 1줄뿐이면 둘째 줄에 `-`를 쓴다. 화면 프로그램이 묶음을 항상 2줄로 읽기 때문이다. 예: 곡 끝의 태그 `주님 곧 오실 때까지` / `-`. 가사가 없는 파트(Intro, Interlude, Outro, 기도 등)는 묶음을 만들지 않고 건너뛴다. `-`만 있는 빈 화면도 만들지 않는다.

### 5. 송폼 순서대로 펼쳐 쓰기

송폼에 나온 순서 그대로 가사를 적는다. 후렴이 네 번 나오면 후렴 가사를 네 번 다 적는다. 이 파일이 그대로 자막 순서가 되기 때문이다.

- 같은 파트가 반복될 때 가사가 달라지면(예: 2번째 후렴 마지막 줄만 다름, 1.·2. 괄호, 키업 버전) 그 반복 차례에 맞는 가사를 쓴다.
- 브릿지를 반복하는 것처럼 송폼에 `*2`가 있으면 그만큼 펼친다.

## 출력 형식

UTF-8 `.txt` 파일 하나.
- 파일 이름: 한 곡이면 `<곡 제목>.txt`, 여러 곡이면 `<첫 곡 제목> 외 N곡.txt`. 제목을 모르면 원본 파일 이름을 쓴다.
- 저장 위치: 사용자가 말하지 않았으면 원본 악보와 같은 폴더.

각 곡은 **제목 묶음**(제목 / `-`)으로 시작하고, 이어서 가사 묶음이 나온다. 곡과 곡 사이에도 빈 줄 하나만 둔다.

```
곡 제목
-

(가사 1줄)
(가사 2줄)

(가사 1줄)
(가사 2줄)

(가사 1줄)
-

다음 곡 제목
-

(가사 1줄)
(가사 2줄)
```

넣지 않는 것:
- 파트 라벨(`[V1]`, `[C]`)
- 송폼 줄
- 코드, 계이름, 반복 기호, 셈여림
- 악보의 손글씨 메모(`윤지 화음`, `잔잔~`, `Key up` 등)

화면에는 가사만 떠야 한다. 송폼과 메모 내용은 작업 후 사용자에게 말로 알려 준다.

전체 예시는 `references/example.txt`에 있다.

## 확실하지 않을 때

악보가 흐리거나, 손글씨이거나, 잘려 있으면 추측한 글자 뒤에 `[?]`를 붙인다(`주님의 사[?]랑`). 사용자가 화면에 올리기 전에 찾아서 고칠 수 있게 하려는 것이다. 작업이 끝나면 사용자에게 다음을 짧게 알린다.

- 저장한 파일 경로
- 사용한 송폼 (악보에 있었는지, 추정했는지, 지워진 칸이 있었는지)
- `[?]`를 붙인 곳, 줄 나눔이 애매했던 곳
